# Miniscuplter v0.6

v0.6 is based directly on v0.5.5 and keeps all earlier release branches unchanged.

## Main milestone

Universal skeleton editing and posing infrastructure for miniature meshes.

## Added

- `Quick Rig`: fast geometry-derived skeleton generation that does not assume a humanoid topology.
- `Universal AI Rig`: provider adapter using the same Miniscuplter skeleton JSON contract. A configured external universal rigger can supply arbitrary skeleton topology.
- Backend `/rig/status` and `/rig/predict-skeleton` endpoints.
- Skeleton visualization inside the viewport using joint markers and bone links.
- Joint list and joint selection.
- Editable joint rest positions.
- Add joint, delete leaf joint and reparent joint controls with cycle protection.
- Object roles: Character, Attachment and Do Not Rig.
- Per-joint XYZ pose rotation controls.
- CPU pose preview using smoothly blended nearest-joint deformation.
- Reset Pose and Apply Pose.
- Pose application updates the editable rest mesh so sculpting/remeshing can continue afterward.
- Rig jobs use the existing v0.5 learned ETA history system.
- `.msculpt` project format version 3 persists rigs, joint hierarchy, pose data and object roles.

## Quick Rig design

Quick Rig performs PCA over the selected mesh, builds an axial chain along the dominant geometry axis, and adds branch chains along meaningful secondary/tertiary extents. This deliberately avoids hard-coding human joint names, so unusual creatures, machines, quadrupeds and elongated forms receive an editable starting skeleton rather than a forced humanoid rig.

Quick Rig is intended to be fast and predictable, not anatomically intelligent. The user should refine the generated joints before final posing.

## Universal AI Rig provider

The backend supports `MINISCULPTER_UNIVERSAL_RIG_COMMAND`. The configured provider must write Miniscuplter skeleton JSON containing a `joints` array with `name`, `parent` and world-space `position` values.

This adapter is intentionally separated from the editor so UniRig-class or future arbitrary-topology riggers can be swapped without changing the pose system.

The current official UniRig ecosystem is relevant because it predicts diverse skeleton hierarchies and skinning, but its published GPU requirements exceed an 8 GB GTX 1080 configuration. v0.6 therefore keeps Quick Rig usable on lower hardware and does not pretend the official heavy AI provider is locally validated on that GPU.

## Current posing model

v0.6 uses a CPU deformation preview. Vertices are influenced by the nearest three joints using inverse-distance weights, then transformed from each joint's rest frame into its posed frame. This provides a practical first skinning/pose workflow for STL-oriented meshes.

It is not yet equivalent to production-quality learned skin weights. A future provider can supply better skinning weights without changing the saved skeleton hierarchy.

## Recommended test

1. Select a creature mesh and mark it Character.
2. Mark weapons/base/debris Attachment or Do Not Rig.
3. Run Quick Rig.
4. Inspect the generated joint hierarchy.
5. Move/reparent/add/delete joints as needed.
6. Rotate several joints and preview the pose.
7. Reset Pose.
8. Pose again and Apply Pose.
9. Save the `.msculpt` project and reload it.
10. Voxel-remesh the applied pose if printable topology cleanup is needed.
