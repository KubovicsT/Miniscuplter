# Miniscuplter v0.4

v0.4 is based directly on v0.3 and keeps all earlier branches unchanged.

## Added in v0.4

- CPU voxel remesh backend using trimesh
- Voxel Remesh Selected command
- Voxel Union All Objects command
- Adjustable voxel size in millimetres
- Preserve-originals option for non-destructive testing
- Reconstructed STL is loaded back into Miniscuplter automatically
- Geometry-context capture alongside the viewport image
- Geometry context stores camera FOV, near/far planes, camera transform, viewport size, per-object transforms and AABBs
- Backend reports a geometry provider in `/health`

## Why voxel remesh matters

AI-generated and kitbashed meshes commonly contain overlapping shells, inconsistent topology, disconnected surfaces and very uneven triangle density. Voxelization converts the visible geometry into an occupancy volume and reconstructs a fresh surface. This gives Miniscuplter a practical first bake/union path before a future native SDF/OpenVDB backend.

## Current limitations

This first implementation is CPU based and is intended for correctness/testing rather than maximum performance. Very small voxel sizes on large models can use substantial RAM and processing time.

The geometry-context bundle currently records RGB plus camera/object metadata. True depth and normal render buffers, automatic generated-part placement from those buffers, localized surface replacement, subtractive SDF operations and a native OpenVDB backend remain future work.

Skeleton generation and posing are intentionally not part of v0.4; the roadmap for v0.4 remains geometry-aware AI editing and remesh infrastructure.
